# B1 Amendment - profiles migration

## Contexto Temporal

A migration `20260913000000_profiles.sql` foi aplicada ao Supabase Cloud
com um rascunho v0.2 que continha 2 policies vulneraveis:

- `Users update own profile` (UPDATE) - escalada de privilegio BQ-01
- `Admins read all profiles` - recursao RLS BQ-02

## Correcao Aplicada

| Etapa | Onde | Acao |
|:---|:---|:---|
| B1-FIX-02 | Remoto (query direta) | DROP das 2 policies vulneraveis |
| B1-FIX-03 | Local (git) | Amend do ficheiro com DROPs defensivos |

## Estado Final

- Remoto: 1 policy (Users read own profile / SELECT) + trigger + funcao
- Local (git): migration idempotente com 3 DROP POLICY IF EXISTS defensivos

## Divergencia de Hash

O hash local da migration difere do hash registado no remoto.
`supabase db push` skipa esta migration por ja estar aplicada.

Debito DT-FE-13: alinhamento de hash local<->remoto pendente.
Nao bloqueia MVP. `supabase db reset` local re-aplicara a versao corrigida.

## Nao E Debito

O estado final e seguro. As policies vulneraveis nao existem em nenhum ambiente.
